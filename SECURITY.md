# Security policy

## Что содержит приватного

- `data/auth.json` — токен и cookies вашей DeepSeek сессии. Это доступ к вашему
  аккаунту. Не коммитьте, не публикуйте, не отправляйте другим.
- `data/sessions.json` — служебные ссылки на DeepSeek-сессии.
- `data/chrome-profile/` — отдельный профиль Chrome для входа. Содержит локальные
  данные браузера.
- `.env` — локальные настройки и необязательный `PROXY_API_KEY`.

Все перечисленные файлы исключены из Git через `.gitignore`.

## Правила безопасности

- Bridge по умолчанию слушает только `127.0.0.1`.
- Для не-loopback `HOST` требуется `PROXY_API_KEY` длиной не менее 24 символов;
  ключи сравниваются constant-time.
- CORS разрешён только для loopback-источников, если явно не заданы дополнительные.
- Логины и пароли DeepSeek не сохраняются.
- Token, cookie, authorization и Bearer-значения удаляются из логов.
- TLS-проверка upstream не отключается.
- CAPTCHA и 2FA пользователь проходит вручную; Bridge не пытается их обойти.
- Bridge не выполняет инструменты сам — он только передаёт запросы клиенту.

## Что делать при утечке

Если `data/auth.json` или токен попали наружу — выйдите из аккаунта на
`chat.deepseek.com`, повторите `npm run auth` и смените пароль.

## Сообщить об уязвимости

Сначала повторите `npm run auth` и `npm run doctor`. Если проблема связана с
приватными данными в логах, сообщите в репозиторий приватно. Не вставляйте
token, cookie и полные пути в issue.
